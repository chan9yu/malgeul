# ui-conventions

말글 화면을 코드로 옮기는 규칙이다. 배치와 상태의 정본은 `docs/design/DESIGN-SPEC.md`, 색과 타이포그래피, 컴포넌트의 정본은 `docs/design/DESIGN.md`, 동작과 문구의 정본은 `docs/product/SPEC.md`다. 구현 전에 셋을 읽는다. 여기에는 정본을 코드로 옮길 때의 규칙만 적는다.

## 색 토큰

DESIGN.md의 색 표를 CSS 커스텀 프로퍼티로 옮기고 이름을 그대로 쓴다. `--color-brand`, `--color-text-sub`처럼 표의 이름과 코드의 이름이 일치해야 qa-inspector가 표와 CSS를 기계적으로 대조할 수 있다. 컴포넌트에서 hex 값을 직접 쓰지 않는다. 값이 흩어지면 색을 바꿀 때 누락이 생기고 대조도 불가능해진다.

## 타이포그래피와 폰트

- Pretendard woff2 서브셋을 저장소 자원으로 함께 배포한다. CDN 링크를 쓰지 않는 이유는 프라이버시가 제품의 존재 이유라서다. 개발자 도구 네트워크 탭에 폰트 외부 요청이 보이는 순간 "아무것도 나가지 않는다"는 인상이 깨진다
- 폴백 스택과 크기 체계는 DESIGN.md의 표를 그대로 쓴다
- 타임스탬프에는 `font-variant-numeric: tabular-nums`를 건다. 고정폭 숫자가 아니면 재생 중 강조가 옮겨 다닐 때 목록이 흔들려 보인다
- 간격은 8px 배수, 모서리 반경은 8px, 그림자는 쓰지 않는다

## 화면 상태 머신

앱 상태는 DESIGN-SPEC의 상태 전이 표를 그대로 union 타입으로 옮긴다. 업로드, 변환 확인, 변환 진행, 결과, 실패 안내 다섯에 비지원 브라우저 안내가 접속 시점 판별로 따로 있다. 전이는 표에 있는 것만 만든다. 표에 없는 전이를 코드에 넣으면 무단 전이고, 표에 있는데 코드에 없으면 죽은 전이다. 둘 다 qa-inspector가 잡는 대상이다.

비지원 브라우저 판별은 `navigator.gpu` 존재 여부다. SPEC 실패 처리 절에 있다.

## 문구

거절 문구와 안내문, 실패 문구는 SPEC과 DESIGN-SPEC의 문자열을 글자 그대로 쓴다. 임의로 다듬으면 문서와 코드가 어긋나고, qa-inspector의 문구 대조에서 실패로 잡힌다. 더 나은 문구가 떠오르면 코드에서 바꾸지 말고 리더에게 문서 수정을 제안한다.

## 업로드 검증

SPEC의 검사 순서(개수, 확장자, 크기, 길이)를 그대로 코드 순서로 만든다. 처음 걸린 항목 하나의 이유만 보여준다.

영상 길이는 파일을 디코딩하지 않고 읽는다. `URL.createObjectURL(file)`을 video 요소의 src에 넣고 loadedmetadata에서 duration을 읽은 뒤 `URL.revokeObjectURL`로 해제한다. 메타데이터를 읽지 못하면 SPEC의 메타데이터 거절 문구를 쓴다.

## 파이프라인과의 경계

파이프라인의 공개 타입(구간, 진행 이벤트)은 pipeline-dev가 정의한다. 화면에 필요한 shape이 없으면 지어내거나 캐스팅으로 우회하지 말고 pipeline-dev에게 요청한다. `as`로 눌러 놓은 타입 불일치는 컴파일은 통과하지만 런타임에 터지고, 그 시점에는 원인을 찾기 어렵다.

진행 화면에는 표시가 두 종류라는 점을 놓치기 쉽다. 모델 다운로드 중에는 내려받은 용량("312MB / 600MB")을, 음성 추출과 변환 중에는 백분율을 보여준다. 진행 이벤트 타입에서 이 둘을 구분해 받는다.

## 코드 스타일

- 함수형 컴포넌트만 쓴다. import 정렬은 eslint의 simple-import-sort가 강제하므로 저장 전에 lint:fix를 돌린다
- 컴포넌트 이름은 DESIGN.md 컴포넌트 목록의 이름을 영어로 옮겨 쓴다. 문서의 "진행 표시"가 코드의 ProgressIndicator가 되는 식으로, 문서와 코드를 오가며 찾을 수 있어야 한다
- 파일을 어느 폴더에 둘지는 AGENTS.md의 소스 구조 표가 정한다. 역할별이고 기능별로 묶지 않는다. 구조 변경은 사용자 확인이 필요하다

## 함정

**`use`로 시작하는 함수 이름은 훅으로 취급된다.** `eslint-plugin-react-hooks`는 파일 확장자와 이름만 보고 판정한다. React를 가져오지 않은 `.ts` 파일이어도 `useBundledWasmRuntime` 같은 이름을 쓰면 훅 규칙에 걸려 lint가 깨진다. 훅이 아니면 `use`로 시작하지 않는 이름을 붙인다. 화면 폴더 밖에서도 마찬가지다.

**같은 값으로 setState하면 다시 그리지 않는다.** 그래서 값 하나로 타이머를 다시 시작시킬 수 없다. "복사했습니다"를 2초 뒤 되돌리는 동안 다시 누르면 상태값이 같아 effect가 다시 돌지 않고, 처음 누른 시각을 기준으로 사라진다.

누른 횟수를 세는 값을 하나 더 두어 effect를 다시 돌리는 방법이 먼저 떠오르는데, 그것은 상태를 흉내 내는 플래그다. 되돌릴 타이머를 ref에 들고 있다가 누를 때마다 `clearTimeout`으로 지우고 새로 건다.
