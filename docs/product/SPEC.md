# SPEC

각 기능이 정확히 어떻게 동작하는지 정한다. 누구의 어떤 문제를 왜 푸는지는 `product/PRD.md`에, 각 화면에 무엇이 놓이는지는 `design/DESIGN-SPEC.md`에 있다. 기술 결정 기록은 이 문서의 마지막 절이다.

## 동작 규칙

### 업로드 검증

파일을 받으면 아래 순서로 검사한다. 처음 걸린 항목 하나의 이유만 보여주고 거절한다. 거절해도 업로드 영역은 기본 상태로 돌아가 다른 파일을 바로 받을 수 있다.

1. 개수: 한 번에 한 파일만 받는다. 두 개 이상을 끌어다 놓으면 거절한다
2. 확장자: 파일 이름이 `.mp4`나 `.mov`로 끝나야 한다. 대소문자는 가리지 않는다
3. 크기: 2GB(2,147,483,648바이트)를 넘으면 거절한다
4. 길이: 영상 메타데이터에서 재생 시간을 읽어 2시간(7,200초)을 넘으면 거절한다. 메타데이터를 읽지 못하는 파일도 여기서 거절한다

거절 문구는 걸린 이유를 그대로 말한다.

| 걸린 검사  | 문구                                                       |
| ---------- | ---------------------------------------------------------- |
| 개수       | 파일은 한 번에 하나만 받습니다                             |
| 확장자     | mp4나 mov 파일만 받습니다                                  |
| 크기       | 2GB를 넘는 파일은 받을 수 없습니다                         |
| 길이       | 2시간을 넘는 영상은 받을 수 없습니다                       |
| 메타데이터 | 영상 정보를 읽지 못했습니다. 파일이 손상되었을 수 있습니다 |

검사를 모두 통과하면 변환 확인 화면으로 넘어가 파일 이름과 크기, 재생 시간을 보여준다. 변환은 사용자가 "변환 시작"을 눌러야 시작한다.

### 변환 파이프라인

변환은 모델 준비와 음성 추출, 변환 세 단계를 차례로 지난다. 화면에는 세 단계가 목록으로 보이고 지금 단계의 진행률이 그 아래에 붙는다.

**모델 준비.** 브라우저 캐시에 음성 인식 모델이 있는지 먼저 확인한다. 없으면 약 600MB를 내려받고 내려받은 용량을 "312MB / 600MB" 형식으로 보여준다. 받은 모델은 브라우저 캐시에 저장한다. 캐시에 모델이 있으면 다운로드 없이 캐시에서 읽어 이 단계가 짧게 끝난다.

**음성 추출.** 영상 파일의 오디오 트랙을 브라우저 내장 디코더로 해독하고 음성 인식이 받는 형식인 16kHz 모노 PCM으로 바꾼다. 오디오 트랙이 없거나 해독에 실패하면 실패 안내 화면으로 간다.

**변환.** 추출한 음성을 한국어 텍스트로 바꾼다. 진행률은 전체 음성 길이 가운데 처리를 마친 시간의 백분율로 보여준다. 결과는 구간 단위로 나오고 구간마다 시작 시각과 끝 시각이 붙는다.

세 단계가 모두 끝나면 결과 화면으로 간다. 중단 버튼은 없다. 모든 처리가 기기 안이라 새로고침으로 처음부터 다시 하면 되고 잃는 것은 시간뿐이다.

### 결과

**문장과 시작 시각.** 문장 단위는 음성 인식이 나눈 구간을 그대로 쓴다. 화면의 문장 목록과 txt, 전체 복사에서 시작 시각의 표기는 영상 길이가 1시간 미만이면 `mm:ss`, 1시간 이상이면 `h:mm:ss`로 통일한다.

**문장 클릭.** 문장 행을 클릭하면 플레이어가 그 문장의 시작 시각으로 이동해 재생한다. 일시정지 상태였어도 재생을 시작한다. 재생 중에는 현재 재생 시각이 시작 시각 이상이고 다음 문장의 시작 시각 미만인 문장을 재생 중인 문장으로 판정해 목록에서 강조한다.

**전체 복사.** 아래 txt 형식과 같은 내용을 클립보드에 복사한다.

**내려받기.** 파일 이름은 원본 영상 이름에서 확장자만 바꾼다. `meeting.mp4`를 변환하면 `meeting.txt`와 `meeting.srt`, `meeting.vtt`가 된다. 인코딩은 셋 다 UTF-8이다.

txt는 한 문장이 한 줄이고 줄 앞에 시작 시각을 대괄호로 붙인다.

```
[00:03] 안녕하세요, 오늘 회의를 시작하겠습니다.
[00:07] 지난주에 이야기한 일정부터 확인하겠습니다.
```

srt는 자막 번호와 시간 범위, 문장을 빈 줄로 구분해 쌓는다. 번호는 1부터 차례로 붙이고 시각은 시, 분, 초를 콜론으로 잇고 밀리초를 쉼표로 구분한다. 끝 시각은 음성 인식이 준 구간의 끝 시각이다.

```
1
00:00:03,200 --> 00:00:07,500
안녕하세요, 오늘 회의를 시작하겠습니다.

2
00:00:07,500 --> 00:00:12,000
지난주에 이야기한 일정부터 확인하겠습니다.
```

vtt는 첫 줄에 `WEBVTT`를 쓰고 빈 줄 뒤에 시간 범위와 문장을 쌓는다. 시각 표기는 srt와 같되 밀리초를 마침표로 구분한다.

```
WEBVTT

00:00:03.200 --> 00:00:07.500
안녕하세요, 오늘 회의를 시작하겠습니다.

00:00:07.500 --> 00:00:12.000
지난주에 이야기한 일정부터 확인하겠습니다.
```

### 실패 처리

**비지원 브라우저.** 접속하면 먼저 WebGPU를 쓸 수 있는지(`navigator.gpu` 존재 여부) 확인한다. 없으면 업로드 화면 대신 비지원 브라우저 안내를 보여준다. 데스크톱 Chrome이나 Edge 최신 버전으로 열어 달라는 내용과 영상을 서버에 올리지 않고 브라우저 안에서만 처리하는 방식이라 이 브라우저들이 필요하다는 이유를 함께 적는다.

**음성 추출 실패.** 오디오 트랙이 없거나 내장 디코더가 해독하지 못하는 파일이면 실패 안내 화면으로 간다. 문구는 "이 파일에서 음성을 찾지 못했습니다"처럼 무엇이 안 됐는지 밝힌다. "다른 파일 선택" 버튼으로 업로드 화면에 돌아간다.

**변환 진행 중 그 밖의 실패.** 모델 다운로드가 네트워크 문제로 끊기거나 음성 인식 중 오류가 나도 같은 실패 안내 화면으로 간다. 문구에 어느 단계가 실패했는지 적는다.

## 기술 결정 기록

아이디에이션에서 확정한 결정과 이유를 남긴다. 결정을 바꾸면 이 절을 고친다.

### 음성 인식: transformers.js로 Whisper를 브라우저에서 실행

모델은 whisper-large-v3-turbo 양자화 버전(약 600MB)을 쓰고 WebGPU로 가속한다. 한국어 인식 품질이 제품의 존재 이유라서 작은 모델 대신 큰 모델을 골랐다.

### 오디오 추출: 브라우저 내장 디코더만 사용

OfflineAudioContext로 영상 파일의 오디오를 디코딩한다. 의존성이 없고 Chrome에서 mp4와 mov의 AAC 오디오를 디코딩할 수 있다. ffmpeg.wasm은 지금 붙이지 않는다. 내장 디코더로 열지 못하는 파일이 실제로 나오면 그때 붙일 대비책으로만 기록해 둔다.

### 모델 캐시: 브라우저 캐시에 저장

내려받은 모델을 브라우저 캐시에 저장해 두 번째 방문부터는 다운로드 없이 바로 시작한다. PRD 성공 기준이 요구하는 동작이다.

### 지원 브라우저: 데스크톱 Chrome과 Edge 최신 버전만

변환 속도가 WebGPU에 달려 있어 WebGPU가 되는 이 둘만 지원한다. WebGPU 없이 도는 폴백 경로는 만들지 않는다.

### 배포: GitHub Pages 정적 배포

서버가 없는 정적 사이트라 GitHub Pages로 충분하다. GitHub Pages는 응답 헤더를 마음대로 설정할 수 없지만 오디오 추출에 내장 디코더를 쓰는 방식은 COOP와 COEP 헤더가 필요 없어서 문제가 되지 않는다.

### 스택: React 19와 Vite 8, TypeScript

저장소에 이미 셋업되어 있는 구성을 그대로 쓴다.
