# ROADMAP

무엇을 어떤 순서로 만드는지 정한다. 범위는 `product/PRD.md`가, 각 기능의 동작은 `product/SPEC.md`가, 화면 배치는 `design/DESIGN-SPEC.md`가 정한다.

## 마일스톤

위에서 아래 순서로 만든다. 브라우저 안에서 한국어 음성 인식이 실제로 되는지가 이 제품의 가장 큰 기술 위험이라서 화면보다 먼저 확인한다. 오디오 추출 검증과 음성 인식 파이프라인은 정식 화면 없이 임시 개발 페이지에서 확인하고 화면은 그 뒤에 만든다.

각 마일스톤에는 끝났을 때 눈으로 확인할 수 있는 상태를 한 줄로 적는다.

### 오디오 추출 검증

기술 결정 기록대로 의존성 없이 OfflineAudioContext만으로 mp4와 mov의 오디오를 음성 인식이 받는 16kHz 모노 PCM으로 뽑을 수 있는지 확인한다.

끝난 상태: 임시 개발 페이지에 mp4와 mov 파일을 넣으면 추출한 음성이 브라우저에서 재생되어 들린다.

### 음성 인식 파이프라인

transformers.js로 whisper-large-v3-turbo 양자화 모델을 WebGPU에서 돌려 추출한 음성을 한국어 텍스트로 바꾼다. 모델 다운로드 진행률과 브라우저 캐시 저장, 구간별 시작과 끝 시각, 변환 진행률까지 이 단계에서 확인한다.

끝난 상태: 임시 개발 페이지에 짧은 한국어 영상을 넣으면 시작 시각 붙은 문장 목록이 나오고 두 번째 실행은 모델 다운로드 없이 시작한다.

### 업로드와 진행 UI

공통 틀(헤더, 푸터)과 업로드, 변환 확인, 변환 진행 화면을 만들고 SPEC의 업로드 검증 규칙과 파이프라인을 잇는다. 비지원 브라우저 안내와 실패 안내 화면도 여기서 만든다.

끝난 상태: 파일을 끌어다 놓으면 검증과 변환 확인을 거쳐 진행 화면이 세 단계와 진행률을 보여준다.

### 결과 화면과 내보내기

고정 플레이어와 문장 목록의 2단 결과 화면을 만들고 전체 복사와 txt, srt, vtt 내려받기를 붙인다.

끝난 상태: 변환이 끝난 화면에서 문장을 클릭하면 그 시점부터 재생되고 세 형식의 파일을 내려받을 수 있다.

### 배포와 성공 기준 확인

GitHub Pages에 배포하고 PRD의 성공 기준 세 가지를 배포된 주소에서 확인한다.

끝난 상태: 배포 주소에서 1시간짜리 실제 회의 녹화를 변환해 srt로 내려받고, 네트워크 탭에 영상 전송이 없고, 재방문에서 다운로드 없이 시작하는 것까지 확인했다.

## 남은 수동 확인

체크가 남은 항목은 전부 사람이 눈과 귀로 봐야 하는 것이다. 무엇을 어떻게 보는지 적는다.

### 추출한 음성이 정상으로 들리는지

`pnpm dev`로 서버를 띄우고 `http://localhost:3600/malgeul/dev.html`을 연다. 빌드 입력이 `index.html` 하나라서 이 페이지는 개발 서버에만 있다.

`pnpm preview`나 배포 주소에서 같은 경로를 열면 404가 나지 않고 본 화면이 나온다. 없는 경로를 `index.html`로 되돌리는 기본 동작 때문이다. 업로드 화면이 보이면 개발 서버가 아닌 곳을 연 것이다.

mp4나 mov를 고르고 "추출만 실행"을 누르면 16kHz 모노 PCM이 wav로 재생된다. 말이 알아들을 수 있게 들리고 속도가 원본과 같으면 통과다. 빨라지거나 느려지면 샘플레이트가 어긋난 것이고, 목소리가 겹쳐 들리면 다운믹스가 잘못된 것이다.

샘플레이트와 길이, 신호 세기 같은 숫자는 `node scripts/qa/measure-audio.mjs <파일>`이 이미 잰다. 숫자가 맞아도 소리가 이상할 수 있어 한 번은 사람이 듣는다.

### 배포 주소에서 성공 기준 셋

PRD의 성공 기준 세 가지이고 위 체크리스트의 마지막 세 항목이다. 배포한 뒤 배포 주소에서 확인한다.

두 번째와 세 번째는 `node scripts/qa/capture-requests.mjs`가 로컬 미리보기에서 자동으로 확인하고 있다. 그래도 배포 주소에서 다시 보는 것이 성공 기준이다. 로컬과 배포는 경로가 달라서 로컬에서만 맞는 경로가 있을 수 있다.

### 화면을 눈으로 보는 것

스크립트는 문구와 요소의 존재를 확인할 뿐 배치가 보기 좋은지는 판정하지 못한다. 아래를 사람이 본다.

- 실제로 파일을 끌어다 놓아 업로드 영역이 브랜드 색으로 바뀌는지
- 결과 화면 2단 배치에서 플레이어가 목록을 스크롤해도 따라오는지
- 내려받은 txt와 srt, vtt를 열어 자막이 영상에 맞게 붙는지

### 배포 전에 해야 하는 설정

저장소 Settings의 Pages에서 Source를 GitHub Actions로 바꾼다. 아직 Pages가 켜져 있지 않아 지금 푸시하면 워크플로가 산출물을 올리는 마지막 단계에서 실패한다.

저장소 이름은 `malgeul`로 바꿔 두었다. 빌드 `base`가 `/malgeul/`이라 이름이 다르면 배포 사이트의 모든 자원이 404가 된다.

## 이후 후보

PRD가 범위에서 제외한 것 가운데 나중에 다시 볼 만한 것을 모아 둔다. 지금은 만들지 않는다.

- 재생 중인 문장으로 목록 자동 스크롤: 긴 영상에서 강조된 행이 화면 밖으로 나간다. 지금 핵심 시나리오는 문장을 눌러 그 시점을 확인하는 쪽이지 재생을 따라 읽는 쪽이 아니라서 넣지 않았다
- 화자 분리: 누가 말했는지 구분한다
- 결과 텍스트 편집: 지금은 복사해서 밖에서 고친다
- 오디오 파일 업로드: mp3와 m4a 등을 영상 없이 받는다
- 한국어 외 언어: Whisper 모델 자체가 다국어를 지원해 확장할 여지가 있다
- ffmpeg.wasm 대비책: 내장 디코더로 열지 못하는 파일이 실제로 나오면 붙인다. 기술 결정 기록에 대비책으로 적어 두었다
- 다른 브라우저 지원: Safari와 Firefox의 WebGPU 지원이 안정되면 다시 본다

로그인과 계정, 서버 저장은 후보에도 넣지 않는다. 영상이 기기 밖으로 나가지 않는다는 제품의 전제와 어긋난다.
